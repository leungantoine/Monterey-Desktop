Their installers and executables were not run. Version 1.2 implemented the ideas below; version 1.3 adapts WindowServer preparation record layouts, attributed in `THIRD_PARTY_NOTICES.md`.

Further inspection of Matthew Lam's `docs/architecture/background-control-contract.md`, input delivery planning, and SkyLight transport informed explicit background mode and the refusal to fall back to foreground input. Basic per-process pointer posting silently failed in Safari on this Mac, and setting `AXFocused` directly raised Safari. The final Monterey backend uses target-only WindowServer preparation and window-local pointer locations, with independent Safari callbacks proving delivery. It avoids newer-system authentication memory patches and is disabled outside macOS 12.

## Differences and limits

`state_changes` compares the pre-batch and post-batch snapshots, not each individual action, and is returned without another capture or tool call. It reports coverage limits, secure-field redaction, target changes, and fresh IDs only on the after-state. UI changes can be unrelated to the action; verify the specific expected outcome with the refreshed UI and `wait_for`.

Exact window matching uses native AX window IDs when available and visible CoreGraphics metadata. Unique AX bounds are a fallback; ambiguity fails instead of choosing arbitrarily. A selected-window readiness condition remains in that window. A partially traversed tree cannot prove selector uniqueness.

Foreground mode retains normal desktop input. Version 1.3 background mode adds process/window-targeted input and guard checks. The live fixture verifies simultaneous foreground user typing and background Safari typing without crossing streams, pointer movement, or app activation. Version 1.4 extends discovery and observation to other Spaces with explicit `space_scope=all`. The default stays active-Space only; the helper does not add a separate display or continuous live viewer.

For v1.4, primary [yabai declarations](https://github.com/asmvik/yabai/blob/master/src/misc/extern.h) and Hammerspoon's [Space bindings](https://github.com/Hammerspoon/hammerspoon/blob/master/extensions/spaces/libspaces.m) informed read-only Space discovery and window membership queries. Hammerspoon's [Space controller](https://github.com/Hammerspoon/hammerspoon/blob/master/extensions/spaces/spaces.lua) also documents limitations of native AX discovery for other-Space windows. The implementation retains verified AX handles, falls back to selected-window screenshots for an unseen inaccessible native tree, and distinguishes ordered off-Space windows from minimized/hidden ones. Test setup alone uses observed Mission Control controls; production Space APIs never switch Spaces or move windows. Managed display ordering was observed to differ from Mission Control Desktop names on this Mac, so metadata reports IDs rather than guessing Desktop numbers.

The live Safari fixture checks two same-app windows, background observation, explicit target focus, wrong-window input rejection, supported controls, independently reported field changes, no-change results, and secret redaction. The existing click, drag, Unicode, readiness, focus, stale-frame, and pause checks also passed.
